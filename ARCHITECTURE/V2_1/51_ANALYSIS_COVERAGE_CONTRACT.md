# Analysis coverage contract

Normative V2.1 repair for finding 6; canonical wire definitions live in SCHEMAS. An empty finding set is never evidence of completed work.

## Authority and pre-execution manifest

The protected Analysis Planner resolves policy and a digest-pinned analyzer registry against the exact candidate/tree and creates ExpectedAnalysisManifestV1 before any mandatory execution. The ordinary API may request planning but cannot insert or amend authoritative manifests. Manifest and its ordered unit set are immutable; changed policy, exclusions, analyzer/configuration, scope, tree or epoch requires a new manifest and superseding evaluation.

The manifest binds AttemptBindingV2 digest, candidate coordinate/tree, policy digest, analysis-plan digest, expected units, each analyzer ID and immutable bundle digest, the effective configuration digest, required scope and file/symbol-set digests, explicit allowed exclusions, sandbox requirements, mandatory build/test units and coverage expectations. Content-addressed referenced sets are canonical, retrievable and checked before scheduling; an absent set blocks planning. Unit IDs are unique in one manifest and deterministically identify analyzer + configuration + scope + execution purpose. A build unit and a test unit are distinct even when one process supplies both; receipts identify each independently.

Policy establishes mandatory checks before repository-controlled configuration is read. Repository settings can only restrict where policy explicitly delegates that setting; the planner records the exact policy clause and resulting exclusion set. A repository cannot turn off security analysis with a local skip flag, an ignore-all file, a zero-file glob, a custom executable, or a model-generated plan. An empty applicable scope requires a planner-authorized exclusion with evidence of the scope calculation, not a fabricated completion.

## Completion and zero findings

Every required unit emits AnalysisCompletionReceiptV1, including successful execution with finding_count = 0. The runner authenticates its report through Runner Control; the protected Evidence Ingestion role verifies session, lease and manifest before inserting the immutable receipt. It binds manifest digest, unit ID, attempt, actual bundle/configuration/scope, actual coverage, findings count, artifact digests, start/end times, producer, epoch and lease generation. Status is COMPLETED, FAILED, UNSUPPORTED or CANCELLED. COMPLETED means the declared work terminated successfully and met the manifest's coverage rule; process exit zero alone is insufficient if required files/tests were skipped. Failed/unsupported/cancelled reports remain auditable, never coverage credit.

Mandatory coverage rules state the exact metric and threshold (for example all 17 listed files scanned, all 4 required build/test units executed, required branch coverage at least the pinned policy threshold). Tool adapters must report trustworthy denominator and actual scope, including skipped units and errors. A signed claim by a compromised runner is not independent truth: evidence provenance and C-class qualification remain required under 13. Missing coverage telemetry or tool crash cannot masquerade as zero findings. Cached artifacts may support a fresh receipt only if policy explicitly permits reuse of exact tree/bundle/configuration/scope and current trust; cache presence itself is no receipt.

## Transaction and reducer

Planning first seals a logical analysis plan without an attempt digest. After Runner Control allocates a lease and immutable AttemptBindingV2, planning locks current candidate/policy/attempt, checks actual lease expiry, and inserts the attempt-bound manifest/expected-unit rows in one transaction before any execution release. Evaluation remains COLLECTING as in 19; there are no extra PLANNING/READY evaluation states. A crashed or expired allocation gets a new attempt and newly sealed manifest, never reuse of old binding. Unique constraints are (evaluation_id, manifest_digest) and (manifest_digest, unit_id); only the protected planner role writes them. Receipt ingestion locks the attempt and checks owner, lease generation, epoch, permitted state and lease_expires_at > database clock at the authorization statement; duplicate receipt ID with equal digest is idempotent, unequal bytes reject. Unique accepted receipt key is (manifest_digest, unit_id, attempt_id, lease_generation); later generation does not mutate old evidence.

The protected gate reducer performs an exact set comparison: every expected mandatory unit has a qualified COMPLETED receipt for the chosen current attempt/manifest; no missing, duplicate-conflicting, foreign or substitution receipt contributes. Optional units cannot replace mandatory ones. It checks effective scope and coverage, analyzer/configuration digests, revoked components, C-class and oracle trust, then required verification and finding policy. Manifest completeness is necessary but not sufficient for PASS. An unavailable mandatory unit yields BLOCKED, HUMAN_REVIEW_REQUIRED or PARTIALLY_AVAILABLE per pinned policy, always non-permitting.

The same transaction that commits evaluation locks its currentness pointer and binds the manifest digest, completion-set digest, verification-set digest, policy/trust-set and authority epoch into gate proof. A late stale receipt is appended as a rejected audit fact, never makes a terminal evaluation current. PostgreSQL access is limited to protected roles; runners, sandboxes and agents use typed mTLS endpoints and hold no database credentials. See the authority/write matrix in 22 and state machine rules in 19.

## Validation

P0-07A removes one zero-finding receipt, substitutes scope and disables a mandatory analyzer through repository configuration; none may produce PASS. P0-07B exercises producer forgery and trust-set revocation. P0-06 binds manifest canonical vectors. ADR-020 records the bounded semantic change.
